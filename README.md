# anyforms-calculate-salary

Сервис расчёта зарплаты Ирины. Запускается в GitHub Actions **1-го и 16-го числа в 10:00 МСК**,
берёт успешно закрытые сделки из amoCRM и проставляет суммы по воронкам в таблицу зарплаты
в Google Sheets.


## Как считает

| Запуск      | Что заполняет                                      |
|-------------|----------------------------------------------------|
| 1-е число   | блок «16 - 31» **предыдущего** месяца              |
| 16-е число  | блок «0 - 15» **текущего** месяца (оплаты 1–15)    |

Сделка попадает в расчёт, если:

- воронка — одна из списка ниже, статус `142` («Успешно реализовано»);
- ответственный — Ирина (`responsible_user_id = 13161462`);
- **дата оплаты** (поле сделки `2364807`) попадает в период — по московскому времени.

Суммируется бюджет сделки (`price`).

| Воронка            | pipeline_id |
|--------------------|-------------|
| Под заказ          | 9784138     |
| Розница            | 10557858    |
| Повторные продажи  | 9939750     |
| Гайд               | 11156742    |
| Курс               | 10863606    |

## Куда пишет

Таблица: `15SuV4LKn_edktKpp6Nwi01kXp9BGDv0gtblvT_HUyBI`, лист месяца называется «Июль 2026»,
«Август 2026» и т.д. В листе два блока: «0 - 15» (подписи в столбце A, суммы в B) и
«16 - 31» (подписи в H, суммы в I).

Рядом с суммой (столбец D для «0 - 15» и K для «16 - 31») сервис пишет список сделок,
из которых она сложилась: суммы через запятую, каждая — кликабельная ссылка на сделку в amo.

Строка воронки ищется по подписи под заголовком блока. Если подписи нет (как было с «Гайд»
и «Курс» в левом блоке июля), сервис пишет подпись и сумму в свободную строку блока; занятые
чужим текстом ячейки не трогает. Формулы («Итог», проценты, прирост) сервис не трогает —
проверь, что «Итог» суммирует все пять строк.

Если листа месяца ещё нет, он создаётся копией листа предыдущего месяца, суммы в копии
очищаются. Формулы «прироста» в скопированном листе могут остаться ссылаться на старый
месяц — их стоит проверить руками (или просто создавать лист заранее самому).

## Секреты (Settings → Secrets and variables → Actions)

| Секрет                    | Что это |
|---------------------------|---------|
| `AMOCRM_SUBDOMAIN`        | поддомен amo, например `mycompany` из `mycompany.amocrm.ru` |
| `AMOCRM_ACCESS_TOKEN`     | долгосрочный токен amoCRM (amo → Настройки → API) |
| `GOOGLE_CREDENTIALS_JSON` | полный JSON ключа сервис-аккаунта Google (можно base64) |

Сервис-аккаунт: в Google Cloud Console создать service account, включить **Google Sheets API**,
выпустить JSON-ключ и дать сервис-аккаунту (его `client_email`) доступ **Редактор**
к таблице зарплаты через «Поделиться».

## Ручной запуск и перезаполнение задним числом

Actions → **Calculate salary** → Run workflow. Поле `period` можно оставить пустым
(посчитается по текущей дате) или указать явно:

- `2026-07:0-15` — первая половина июля;
- `2026-07:16-31` — вторая половина июля.

Перезапись безопасна: сервис просто ещё раз проставит суммы в те же ячейки.

## Локальный запуск

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest -q                     # тесты, по желанию
python -m calculate_salary
```

Переменные можно задать через `export` или положить в файл `.env` в корне проекта
(он в `.gitignore`, скрипт подхватывает его сам):

```
AMOCRM_SUBDOMAIN=...
AMOCRM_ACCESS_TOKEN=...
GOOGLE_CREDENTIALS_JSON=<base64 от JSON-ключа: base64 < service-account.json | tr -d '\n'>
PERIOD=2026-07:16-31
DRY_RUN=1
```

Каждое значение — одна строка (многострочный JSON в `.env` не работает, поэтому base64).
`PERIOD` необязателен (без него — по текущей дате). `DRY_RUN=1` — посчитать и показать,
что было бы записано, но таблицу не трогать.

Дополнительные переменные (по умолчанию зашиты): `GOOGLE_SHEETS_SPREADSHEET_ID`,
`RESPONSIBLE_USER_ID` (13161462), `PAYMENT_DATE_FIELD_ID` (2364807).

## Нюансы

- GitHub может запускать cron с задержкой до нескольких минут — на расчёт это не влияет.
- Если в репозитории 60 дней нет активности, GitHub отключает scheduled workflows —
  придёт письмо, включается кнопкой в Actions.
- При ошибке (amo недоступен, нет листа и т.п.) run падает красным и GitHub присылает
  уведомление; в таблицу при этом ничего не пишется.
